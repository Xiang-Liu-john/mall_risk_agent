

===== 1-1如何做个经营风险预警的agent.docx =====

构建一个经营风险预警 Agent（在 AI 领域通常称为 AI Agent），不能只是让它当一个“传话筒”，而是要让它具备感知（Perception）、规划（Planning）、记忆（Memory）和行动（Action）的完整闭环能力。
相比于普通的数据看板，Agent 的核心优势在于：它能主动监控、深度推理、自动调用工具，并代替人类执行部分止损操作。
下面为您拆解如何从零构建一个实用的“经营风险预警 Agent”的设计方案与开发路径：
🧭 一、 经营风险预警 Agent 的四大核心要素 (FAPM 架构)
要让 Agent 真正跑起来，我们需要在技术架构上为其配置四个核心模块：
┌────────────────────────────────┐
                 │       Memory (记忆模块)        │
                 │   - 历史预警事件 - 商户沟通记录 │
                 └───────────────┬────────────────┘
                                 ▼
┌──────────────┐   ┌────────────────────────────┐   ┌──────────────┐
│  Perception  │   │          Planning          │   │    Action    │
│  (感知模块)  ├──►│         (规划与推理)       ├──►│  (行动与工具)│
│  获取经营数据│   │    大模型结合SOP进行诊断   │   │  派单/发信/招商│
└──────────────┘   └────────────────────────────┘   └──────────────┘
1. 感知 (Perception) —— 喂给 Agent 的“眼睛”
Agent 需要通过 API 或 数据库只读连接 实时或定期读取商场的数据。
结构化数据（硬指标）： 销售额、客流量、提袋率、租售比、拖欠租金天数、合同到期日。
非结构化数据（软信息）： 楼层经理的巡店日志（如“发现该店下午1点未开门”、“店内货架空了一半”）、顾客投诉文本。
2. 规划与推理 (Planning) —— 逻辑大脑与行业 SOP
当 Agent 感知到异常时，不能瞎猜。我们需要通过 Prompt Engineering（提示词工程） 或 Fine-tuning（微调），将商业地产的运营逻辑注入它的大脑。
工作流规划（Workflow）： Agent 发现某店销售额大跌，它会自主规划步骤：
步骤 1：对比同楼层其他品牌，排除是否是区域客流问题。
步骤 2：检查该品牌在全国的舆情（是否有关店潮）。
步骤 3：检查该商户的账单历史，评估资金链风险。
3. 记忆 (Memory) —— 记住商户的历史表现
Agent 必须有“记性”，不能每次分析都像初次见面。
短期记忆： 本次对话中，用户（管理团队）对该商户的批示。
长期记忆（向量数据库/知识库）：
该商户上个月是否也触发了预警？当时采取了什么措施（如：商场给过租金缓缴）？
该商户历史上的沟通态度如何？
4. 行动 (Action/Tools) —— 赋予 Agent 手脚 (Function Calling)
这是 Agent 区别于普通看板的关键。你需要给 Agent 注册一组 Tools（工具/API接口），让它在发现问题后能“干活”：
send_feishu_alert()：向对应的楼层经理推送飞书/钉钉工单。
generate_demand_letter()：自动生成盖章版的《催款警告函》PDF。
search_alternative_brands()：调用招商库 API，匹配替代品牌。
search_news_web()：调用搜索引擎，查询该品牌最近是否有“倒闭/欠薪/跑路”的负面新闻。
🛠️ 二、 落地建设三步走（开发实现路径）
如果您想和团队（或技术外包）开始落地，可以按照以下三个阶段迭代：
第一阶段：基于 Workflow 建立“半自主”Agent（推荐使用 Coze, Dify, LangFlow 等无代码/低代码工具）
这是成本最低、见效最快的做法。利用 Dify 或 Coze 快速搭建：
连接数据源： 将商场的数据表（如 PostgreSQL 或 Excel）作为数据输入节点。
设置定时触发器（Trigger）： 设定每周一早上 9:00 自动运行。
编排 Workflow：
节点 1（代码过滤）： 筛选出“租售比 > 20%”或“销售额连续 3 周下滑超 15%”的商户名单。
节点 2（LLM 分析）： 将筛选出的数据送入 LLM（如 GPT-4o、Claude 3.5 Sonnet），结合商户历史标签进行诊断。
节点 3（工具调用）： LLM 自动生成排版精美的《每周经营风险预警报告》。
节点 4（推送）： 调用企业微信/飞书机器人 API，将报告发送到管理层群，并给对应楼层经理私信派发跟进任务。
第二阶段：引入 RAG（检索增强生成）与招商知识库
让 Agent 变身为真正的“行业专家”：
构建商场运营知识库：
将商场的《商户管理条例》、《合同违约处置流程》、《招商标准品牌库》、《往期成功调改案例》转化为向量数据（Embeddings）存入数据库。
赋能 Agent 决策：
当 Agent 发现某餐饮店连续两个月亏损，触发橙色预警时，它不单单会报警，还会主动去检索知识库：“根据《往期调改案例》，同定位的火锅店曾通过‘大众点评大礼包联动’在 2 周内提升了 18% 客流。建议本次约谈商户时，向其提出该整改方案。”
第三阶段：全自主多 Agent 协同系统 (Multi-Agent System)
当您的系统做大后，可以采用类似 AutoGen 或 CrewAI 的多 Agent 框架，让不同的虚拟角色在后台“开会”解决问题：
┌────────────────────────────────────────────────────────┐
│                      Multi-Agent 协同                  │
│                                                        │
│ ┌─────────────────┐             ┌────────────────────┐ │
│ │  数据分析 Agent  ├────────────►│   商场招商 Agent   │ │
│ │(监控数据、找异常)│ 报告异常商户│ (匹配备胎、出调改) │ │
│ └────────┬────────┘             └─────────┬──────────┘ │
│          │                                │            │
│          │ 报告财务风险                   │ 生成处置方案│
│          ▼                                ▼            │
│ ┌─────────────────┐             ┌────────────────────┐ │
│ │  财务法务 Agent  │             │   运营总监 Agent   │ │
│ │ (出催款函/评估押金)             │(审核、给人类发工单)│ │
│ └─────────────────┘             └────────────────────┘ │
└────────────────────────────────────────────────────────┘
数据分析 Agent（分析师）： 每日扫表，发现某服装店有闭店风险，拉响警报。
财务法务 Agent（风控官）： 收到警报，立刻核查该商家押金是否充足、有没有欠费，自动拟定《风险备忘录》。
商场招商 Agent（猎头）： 收到警报，自动去招商库中筛选 3 个备选女装品牌，生成《铺位调整意向报告》。
运营总监 Agent（协调官）： 整合上述所有信息，最终输出一份结构极其完整的《关于XX店铺的风险预警及应对预案》，推送到您的手机上，您只需点击“同意”，系统便自动给相关责任人派单。
💡 开发初期需要避开的“坑”
不要让 LLM 碰原始账目： 绝对不要给大模型权限去直接“加减乘除”账单。大模型可能会出现幻觉。所有的财务计算（如欠费总额、租金滑坡百分比）必须由传统代码（SQL/Python）计算好，再将结果传给大模型做逻辑分析。
设定人类确认环节（Human-in-the-loop）： 在 Agent 发展初期，涉及到“给商户发函”、“罚款”或“约谈”等敏感动作，绝对不能让 Agent 自动发送。Agent 的 Action 只能走到“生成草稿并待审批”这一步，必须由您或管理团队确认后才能一键发出去。


===== 1-2请给我细化一下.docx =====

好的，我们来把这个“经营风险预警 Agent”从概念设计，细化落地为一套可以直接交给技术团队去开发、或者你们可以用无代码工具自行搭建的“系统实现白皮书”。
为了让这个 Agent 听得懂、算得准、动起来，我们将从数据结构、Agent 决策大脑（核心 Workflow）、核心 Prompt 模板这三个最关键的层面进行极细致的拆解。
一、 第一步：感知层——给 Agent 的“体检数据表”
大模型不能直接读取杂乱无章的原始数据库。我们需要在后台，通过传统代码（如 Python 或 SQL）将商场数据整合成一张“商户日/周经营画像表”，再把这张表作为上下文（Context）喂给 Agent。
1. 结构化数据输入（JSON 格式示例）
Agent 每次诊断一个商户时，后台自动组装并传入以下标准化数据：

二、 第二步：规划层——Agent 决策工作流（Workflow）
这是 Agent 运转的“灵魂路径”。我们通过一个结构清晰的 Workflow（如在 Dify 或 Coze 中配置的分支），让 Agent 能够按照人类专家的逻辑去思考：
1. 规则预处理（避免 AI 算错数）
规则判定：
若 “欠租天数 > 10天” 或 “租售比 > 25%” $\rightarrow$ 直接强制标记为 【红色重度预警】。
若 “销售额连续 4 周下滑 > 10%” 且 “租售比在 18%~25% 之间” $\rightarrow$ 标记为 【黄色中度预警】。
分配给 Agent： 规则引擎贴好标签后，将 JSON 数据和对应的标签分配给不同的 Agent 提示词模板。
2. 中度风险 Agent 的思考链路（诊断模式）
当判定为黄色中度预警时，Agent 的分析链路如下：
分析定位： 对比自身数据与大盘（conversion_mom 大幅下滑，而 floor_average_sales_mom 稳定 $\rightarrow$ 判定为商户自身商品力/运营问题，非商场客流问题）。
知识检索（RAG）： Agent 检索商场的《营销活动资源库》和《往期服装类品牌挽救成功案例》。
输出方案： 产出包含“现场整改意见”和“商场促销扶持方案”的诊断报告。
3. 重度风险 Agent 的思考链路（风控与备胎模式）
当判定为红色重度预警时，Agent 触发法务与招商双重思考链路：
财务清算： 计算 remaining_deposit_amount（剩余押金）是否能覆盖欠费及接下来的清场周期租金。
法务防线： 检索《合同违约处理条例》，匹配适用的解约与催收法务条款。
备胎匹配（API 调用）： 调用招商系统的意向品牌库，寻找同面积、同定位、且目前处于“待入驻”状态的品牌，作为替代备选。
三、 第三步：Prompt 设计——大模型大脑的“终极指令”
这里为您提供可以直接复制、微调并写入 Dify / Coze 节点的 System Prompt。
模板：中度风险（诊断型）Agent Prompt
# Role: 购物中心精细化运营总监
## Background:
你是一位拥有15年商业地产运营经验的顶级专家。你的任务是针对处于“中度风险（黄色预警）”的商户进行病因诊断。你需要根据商户传入的指标，找出问题根源，并从“商场能提供什么帮助”和“商户自己该如何整改”两个维度，给出极其具体、可落地的止血方案。
## Skill Rules:
1. 【数据穿透】：不要复述数字。要对比销售额下滑、客流下滑和转化率下滑的比例差异。
- 如果客流没跌但销售额暴跌：说明店头吸引力足够，但店内商品不吸引人、价格过高或导购不行（进店转化问题）。
- 如果客流量暴跌：说明商场该区域可能出现了客流动线死角，或者该品牌对客群失去了基本的吸引力。
2. 【因果溯源】：必须结合“同楼层/同品类大盘走势”判断。如果大盘跌它也跌，是商场的问题；如果大盘稳它独跌，是品牌的问题。
3. 【具体而非空洞】：绝对不能给出“提升服务质量”、“加强宣传”这种废话。必须结合商场具体的公域资源（如：中庭、会员积分、官微推文、联合卡券）给出实操方案。
## Output Format:
---
### 🔍 经营病因诊断报告
- **核心症结定位**：[用1句话点出最根本的问题，例如：该店面临典型的“有客流无转化”危机，问题出在商品吸引力和店内导购端，而非商场客流问题。]
- **核心数据佐证**：[简要列出两组关键背离数据，证明你的结论。]
### 🛠️ 挽救与干预方案
#### 1. 商场扶持策略（商场能给什么资源）：
- **客流引导**：[结合商户品类，提出一个利用商场小程序或会员系统定向引流的方案，如：向5公里内高频消费女装的VIP定向推送专属体验券。]
- **空间曝光**：[是否需要利用公共空间，如：下周末安排该品牌在L1层直梯旁进行静态新品策展，为期3天。]
#### 2. 商户限期整改要求（约谈筹码）：
- **陈列与货品要求**：[基于现场巡店笔记（如货架空置），提出明确整改要求。]
- **服务与人员要求**：[基于客诉记录或巡店记录提出整改。]
---
四、 第四步：行动层（Action）——Agent 赋能的“手脚”
当 Agent 运行完上述 Workflow 并生成了报告，它需要将结果转化为行动。你需要为开发团队定义以下 3 个核心 API（Functions）：
1. 自动派发飞书/钉钉任务工单（send_operation_ticket）
逻辑： 只要 Agent 判定为黄色/红色预警，自动向该商户对应的“楼层负责人/AM”推送工单。
工单内容：【店面经营干预工单】
负责AM： 张经理
目标商户： L2层 [XX品牌]
当前问题： 租售比已达 22%，销售环比跌幅全层第一（-18.5%）。
Agent 指派任务： 请于 3 个工作日内约谈店长。约谈重点已由 AI 自动生成，请点击链接查看 [AI约谈指南]。约谈后请在此工单回复商家整改意向。
2. 自动生成法务催款函（generate_legal_doc）
逻辑： 针对红色预警且存在欠费的商户。
动作： Agent 调用模板，自动将商户名称、欠费金额、欠费天数、滞纳金比例填充进 PDF 模板，生成标准的《租金催收警告函》草稿，并发送给商场法务负责人审批。
3. 备胎品牌推荐与自动邮件建联（match_and_pre_contact）
逻辑： 针对红色预警且有极高撤铺风险的商户。
动作：
Agent 调用招商意向品牌库，通过向量相似度计算，匹配出 3 个品类相符、档次匹配（如：定位年轻潮流的中档女装）且目前“在跟进中”的品牌。
自动撰写一封给备选品牌招商总监的开发信草稿：“您好，我是XX购物中心的招商团队。目前我司L2层有一个约150平米的黄金位置（近扶梯口）即将完成品牌升级与调整，贵司此前表达过入驻意向，不知近期是否有档期聊聊具体的落地方案？”
(此信仅保存在系统后台草稿箱，等待招商总监一键确认发送。)
五、 如何循序渐进地把这套产品做出来？
不要试图一步到位开发一个完美无瑕的巨系统。建议按照以下两周迭代法来做：
第 1 周：搞定“数据”和“诊断”。
在 Excel 或是现有的 BI 数据系统里，挑出 5 家经营情况最差的商户数据。
直接把这些数据手动黏贴到 Dify 或 Coze 等平台搭建的 AI Chatbot 中（使用上面提供给你的 Prompt）。
测试 AI 给出的诊断是否切中要害，不断微调 Prompt 的约束词。
第 2 周：搞定“派单”和“流程集成”。
让技术团队写一个简单的脚本，每周一自动将异常数据打包成 JSON 发送给大模型。
打通飞书/钉钉的群机器人，让 AI 每周一早上把写好的《XX商户诊断与扶持建议》自动推送到你们运营团队的群里。
第 3 周及以后： 逐步加入 RAG（让 AI 学习商场的规章制度、招商库），并加入自动生成公函、自动推荐备选品牌的功能。

第一阶段：风险诊断与管理逻辑
提问 1：
我作为购物中心的管理团队，我在分析入驻店铺的经营数据，当我发现部分店铺的经营数据、销售额在波动性持续走低，这个时候我应该注意什么？这个现象会带来哪些严重后果，管理团队应该如何规避风险，避免购物中心收到损失？
作为购物中心（Malls）的管理团队，面对入驻店铺经营数据持续波动走低，这不仅是单一商铺的财务问题，更是购物中心运营健康的
“早期红色预警”
。
以下是从运营管理、财务风控和品牌调整三个维度的深度分析：
一、 关键观察点：除了销售额，你还应注意什么？
当数据走低时，销售额是结果，你需要通过以下指标挖掘“病灶”：
进店率与转化率：
如果商场整体客流没降，但该店进店率下降，说明其品牌吸引力或陈列出现问题；如果进店率正常但转化率下降，说明其产品力、价格竞争力或服务质量在恶化。
库存与陈列状态：
观察店铺货架是否出现空置、补货不及时，或者长期不更新陈列。这通常是资金链紧张、放弃经营或品牌总部支持减弱的信号。
人员异动与士气：
店长或核心导购频繁离职，或者员工出现消极怠工、店面卫生变差。
成本削减行为：
是否频繁关灯关空调、减少物业费缴纳配合度、甚至私下尝试违规外卖或场外交易（为了避开提成/抽成）。
会员复购率：
品牌在商场内的粉丝粘性是否断裂。
二、 可能带来的严重后果（多米诺骨牌效应）
租金欠缴风险：
销售额持续走低直接导致商铺支付能力下降，出现延迟缴纳租金、物业费，甚至最终演变成“撤柜跑路”。
“破窗效应”：
核心位置的店铺如果长期冷清或撤柜，会直接影响周边店铺的客流和经营信心，导致邻近商户也提出减租要求或动摇续租意愿。
商场口碑受损：
消费者对于“好逛”的定义包含品牌丰富度和新鲜感。店铺经营惨淡会导致商场整体形象显得过时、冷清，引发整体客流量的系统性流失。
连锁反应：
品牌供应商可能停止供货，导致店内出现维权投诉，甚至演变成群体性事件（如员工讨薪、会员卡退费难），商场管理方需承担连带声誉风险。
三、 管理团队如何规避风险与减少损失？
1. 建立分级预警机制 (Early Warning System)
红黄绿灯管理：
连续三个月销售环比下降20%或低于坪效均值50%的店铺，列入“红灯”预警。
访谈摸底：
运营经理（Floor Manager）应立即约谈店长或品牌区域负责人，了解是总部策略调整、供应链问题，还是该店管理问题。
2. “扶持”与“汰换”并举
诊断扶持：
流量倾斜：
利用商场公众号、中庭美陈或促销活动为其引流。
联动营销：
策划异业联盟（如餐饮消费满额送零售券），看是否能拉动销售。
主动止损（汰换准备）：
物色替补品牌：
在该店铺合同到期前或出现违约迹象时，招商团队应提前启动该铺位的“预招商”，寻找后备品牌，缩短“掉铺”空置期。
法律风险排查：
审阅租赁合同中的违约条款（如欠费几天可封门、违约金数额、装修残值处理等）。
3. 风险隔离措施
保证金管理：
严格核查履约保证金是否足额。
租金收缴策略：
对高风险店铺采取“月付”甚至“周付”模式，或者要求其通过商场统一收银（POS系统），以确保租金能够优先扣除。
4. 优化租户组合 (Tenant Mix)
如果该类目（如传统快时尚）整体走低，说明是业态老化，管理团队应果断调整楼层定位，引入更具引流能力的业态（如新能源车体验店、潮流运动、社交零售等）。
专家建议：
作为管理团队，此时最忌讳“被动等待”。
数据走低是求救信号也是离场信号。
优秀的Mall管理方会在店铺彻底崩盘前，要么通过专业运营运营手段将其救活，要么通过灵活的招商调整将其“无缝替换”，从而保持整个商业生态的活性。
第二阶段：AI 看板产品设计逻辑
提问 2：
为了让管理团队及时规避风险与主动干预，我想基于各个门店的经营数据，做一个运营预警管理看板，借助大模型的能力，对经营数据进行自动数据分析，以及预警，并让大模型给出一些建议措施。我应该如何设计这个产品功能。
设计一个基于大模型（LLM）驱动的
“购物中心运营预警管理看板”
，不仅是将数据可视化，更核心的是利用 AI 实现从“数据描述”到“诊断建议”的闭环。
以下为您设计的四个核心功能模块及其逻辑架构：
1. 数据集成层：多维“经营全景”输入
大模型需要充足的上下文才能给出精准建议。看板应集成以下数据：
基础经营指标：
销售额、成交笔数、客单价、坪效。
客流监测指标：
提货率（成交笔数/进店人数）、进店率（进店人数/门口过人人数）、停留时长。
财务风控数据：
租售比（租金/销售额）、物业费缴纳记录、水电费波动（突然大幅下降可能是关灯歇业预兆）。
外部环境：
行业基准（同业态均值）、天气、节假日、周边竞品活动。
2. AI 诊断引擎：从“异常发现”到“归因分析”
这是产品的核心。利用大模型对结构化数据进行逻辑推理：
异常智能识别：
传统算法：
设定阈值（如环比下降20%触发预警）。
AI 增强：
大模型识别“非季节性”衰退。例如：“该品牌往年7月因暑期销售额应上升，但今年持平且波动率加大，存在隐性经营风险。”
自动归因分析：
当销售额走低时，AI 自动对比维度：
若
场内客流正常 + 该店进店率下降
→ 归因为：品牌吸引力下降或陈列过时。
若
进店率正常 + 转化率下降
→ 归因为：产品力不足、价格敏感或导购服务问题。
若
租售比突破临界点（如>30%）
→ 归因为：财务杠杆风险。
3. 运营预警看板功能设计
界面应分为三个层次，体现“主动干预”：
第一层：红黄绿灯风险矩阵 (Risk Heatmap)
功能：
自动将所有店铺按风险等级排序。
AI 摘要：
在列表旁显示一句话风险概括（例如：“商户 A：经营性现金流风险高，建议立即核查水电费及库存状态”）。
第二层：智能弹窗与预警卡片
触发机制：
当 AI 监测到持续性走低或突发性异常。
卡片内容：
警示点：
“该店铺已连续 4 周跌出业态均值 1.5 个标准差。”
风险预测：
“根据当前趋势，预计该商户下季度无法足额缴纳租金的概率为 75%。”
第三层：AI 经营顾问（决策支持系统）
功能：
提供针对具体门店的“一店一策”建议。
交互逻辑：
管理人员点击“获取建议”，AI 生成方案：
方案 A（扶持）：
“建议将其纳入下周‘盛夏嘉年华’中庭巡演的联动品牌，并给予商场小程序首页 3 天流量倾斜，观察转化率回升情况。”
方案 B（调整）：
“由于其业态与 B1 层新入驻品牌重合，建议合同到期不续约，启动招商后备库中‘XX品牌’的洽谈。”
方案 C（收网）：
“商户已出现私下转让迹象，建议物业部门加强巡检，防止‘连夜撤柜’，并准备法务函件。”
4. 闭环管理：从“建议”到“工单”
一键转办：
AI 生成的建议可以直接转化为“运营任务工单”，发送给对应的楼层经理（Floor Manager）。
反馈学习：
经理在 App 端反馈干预结果（如“已约谈，品牌方表示正在调货”），大模型记录该反馈，用于修正下次的分析精度。
给您的产品设计建议（Prompt 设计思路）：
在调用大模型时，您的系统底层 Prompt 逻辑应该是：
Role:
资深购物中心运营专家
Task:
分析以下经营数据，识别风险，并给出专业决策。
Data Context:
[门店A数据：近6个月销售额、租售比、同业态平均坪效、进店转化率、欠费天数]
Output Format:
1. 风险评级（高/中/低）
2. 核心病灶（指出最关键的一个数据异常）
3. 后果预测（如果不干预，未来3个月会发生什么）
4. 建议措施（提供3个具体动作：运营引流、合同约谈、招商储备）
技术实现要点：
RAG 增强：
将商场的《招商手册》、《租赁合同模板》和《品牌库》作为大模型的外部知识库，使 AI 建议符合贵司的招商政策和法律条款。
Agent 模式：
允许 AI “查阅”其他门店的历史成功救市案例，进行横向对比推荐。
第三阶段：数据维度与结构化定义
提问 3：
基于刚才的两个问题，我现在要模拟一些经营数据作为数据源；请帮我梳理一下数据源的维度都有哪些
为了支撑 AI 看板进行精准的“异常诊断”与“建议生成”，我们需要构建一个多维度的模拟数据源。
我将数据维度分为
五个核心模块
，这些维度将作为大模型进行推理的“特征值”：
1. 基础信息维度 (Static Data)
门店 ID/名称：
唯一标识。
业态分类：
（如：主力店、餐饮、精品零售、快时尚、儿童娱乐）。
楼层与位置：
（如：B1层、边厅/中岛、动线末端）。
租赁面积 (sqm)：
用于计算坪效。
品牌等级：
（S/A/B/C 级）。
2. 经营指标维度 (Performance Metrics)
销售总额 (GMV)：
环比/同比变动率。
成交笔数：
判断是单价跌了还是人流少了。
客单价 (AOV)：
反映产品定位与消费力波动。
坪效：
每平方米贡献的销售额。
库存周转率：
反映货品新鲜度及资金回笼速度。
3. 客流行为维度 (Traffic & Conversion)
门口过人量 (Passing Traffic)：
商场分配给该区域的原始流量。
进店客流量 (Entry Traffic)：
品牌橱窗及吸引力指标。
进店率：
进店人数 / 门口过人量。
成交转化率：
成交笔数 / 进店人数。
平均停留时长：
反映店铺体验感。
4. 财务与合规维度 (Financial Risk)
租售比：
(月租金 + 抽成) / 月销售额。
欠费总额：
租金、物业费、水电费的滞纳金额。
欠费天数 (DPD)：
逾期时长。
保证金余额：
评估剩余风险覆盖能力。
水电费波动率：
识别是否出现“关灯减损”或提前撤柜征兆。
5. 运营体感维度 (Qualitative/Soft Metrics)
导购离职率：
团队稳定性。
投诉密度：
消费者反馈情况。
陈列更新频率：
品牌经营积极性。
营销活动参与度：
对商场统筹配合度。
异业联动频次：
反映社交零售活性。
6. 外部对比维度 (External Benchmarking)
同业态平均坪效：
判断是品牌问题还是整个行业在衰退。
商场整体客流：
判断是商场整体变冷清了，还是该店独降。
天气与节假日系数：
剔除季节性波动影响。

{ "store_id": "SHOP_001", "name": "XX快时尚", "category": "Retail", "monthly_data": { "sales": 450000, "sales_mom": -15.5, "entry_rate": 0.08, "conversion_rate": 0.12, "rent_to_sales_ratio": 0.35, "utility_drop": 0.20, "staff_turnover": 3 }, "benchmark": { "category_avg_sales": 600000, "mall_avg_traffic_change": -2.0 } }
第四阶段：百家门店看板实战设计
提问 4：
给我设计一个数据看板，要求不少于5类业态，100家门店的数据源，展示运营管理数据，并重点突出预警功能；
已为您完成 100 家门店规模的
智慧运营预警看板 v2.0
的设计与数据模拟。
一、 看板核心设计原则
分级预警：
针对“极高风险”门店采用红色脉冲动画及显眼标识，确保管理层第一时间关注。
多业态覆盖：
涵盖餐饮、精品零售、儿童配套、主力店、生活服务，适配不同经营逻辑。
AI 诊断闭环：
不仅展示数据异常，更通过弹窗形式提供 AI 生成的深度分析与行动工单。
二、 数据集描述 (100家门店)
模拟生成的 CSV 数据源包含以下关键字段：
门店基本信息（ID、名称、业态、楼层、面积）。
本月核心经营数据（销售额、环比变动）。
风控核心指标（租售比、进店率、成交转化、欠费总额、水电波动）。
系统生成的风险得分与风险等级（极高、高、中、低）。
三、 看板功能亮点
风险矩阵面板：
实时展示高危风险门店总数，并以 Feed 流形式推送最新的 AI 预警动态。
业态分布分析：
饼图展示全场品牌占比，帮助评估租户组合多样性。
全局搜索与过滤：
支持按风险等级、门店名称、业态进行精准筛选。
智能诊断交互：
点击“查看智能方案”即可查阅 AI 对该店病灶的专项分析及建议动作（如：法务预案、流量倾斜、核查店面）。
交付说明：
对应的 CSV 数据源文件和 HTML 交互看板文件已分别生成并保存至桌面。管理团队可以通过看板直接进行模拟决策，实现从被动响应到主动管理的数字化转型。
